四、数据结构

所有数据通过 Store 抽象层读写，前缀 bysdash:。

键类型说明
records数组核心数据。所有记录
tags数组登记过的标签
review:YYYY-MM-DD单值每天的复盘内容
_theme单值配色方案
_avatar单值自定义头像（base64，压缩到 400px）
_lastPage / _lastWrite / _lastBackup单值界面状态（不参与同步和备份）
local$pasteRaw单值粘贴过的聊天原文，只留本机，不进云端不进备份
bysdash$secret:syncPass敏感同步密码，独立命名空间，永不进备份

records 条目结构

{
  id: 'xxx',           // 唯一标识（同步合并靠它）
  t: '2026-09-13',     // 记下的日期
  text: '报价单发给王总',
  isTodo: true,        // 是待办还是备忘
  done: false,
  doneAt: '',          // 完成时间（周报统计用）
  due: '2026-09-15',   // 截止日期，可空
  tags: ['XX项目'],     // 标签
  src: '王总',          // 来源（谁说的）
  _u: 1789268285983,   // 修改时间戳（同步合并靠它）
}

同步安全规则（改代码时必须遵守）

  • 数组型数据一律 Store.upsert / softDelete / list，不许用 set 整包覆盖（两端同时改会丢数据）
  • 单值配置才用 Store.get/set
  • 禁止裸用 localStorage.xxx
  • 框架内部键（_lastWrite 等）通过 INTERNAL 数组显式列出，不许写成"下划线开头一律排除"（那样会误伤业务数据）

六之二、手动同步（当前的双端方案）

核心认识：它是「合并」，不是「覆盖」。

情况结果
两边都有的同一条保留修改时间更晚的那份
只有一边有的两个都留着

所以来回导不会丢数据，可以放心操作。

（代码里 Store.importFile 走的是 mergeRemote，不是覆盖式导入。）

标准流程（两个方向都要走一次）

手机 → 电脑：

  1. 手机：「设置 → 数据备份 → 导出备份」
  2. 文件发到微信「文件传输助手」
  3. 电脑：下载那个 json 文件 → 「设置 → 数据备份 → 恢复备份」→ 选中它 → 确认

电脑 → 手机：

  1. 反过来再做一遍（电脑导出 → 微信传手机 → 手机恢复备份）

⚠️ 只做一个方向的话，只有一边的数据会补过去。想两边一样，两个方向都要做。

节奏建议

一周合一次就够了，不用天天弄。周报是电脑上生成的，所以：

  • 平时手机随手记（在路上、会议室）
  • 每周固定一次双向合并
  • 合并完两边就齐了

七、日常怎么用

📱 手机是主设备。 详细操作步骤见同目录的《一周使用指南.md》。

电脑（副设备 / 生成周报用）

双击 index.html，用 Chrome 打开。可拖到任务栏固定。

数据存在浏览器里，永久有效。

手机（主设备）

把 index.html 发到微信「文件传输助手」→ 手机上点开 → 右上角「···」→「用其他应用打开」→ 选浏览器。

⚠️ 三个限制必须知道：

  1. 不能在微信里直接用 —— 微信内置浏览器会清缓存，记的数据会丢。必须跳到系统浏览器
  2. 这样加不到手机桌面（加到桌面需要一个永久网址链接）
  3. iOS 上如果 7 天没打开过，Safari 可能清掉数据 → 所以定期导出备份

备份纪律（重要）

  • 每周导出一次备份，文件丢到百度云 / iCloud 存一份
  • 工作台内置提醒：超过 7 天没备份会在页面顶部显示黄条提醒
  • 换手机、清理浏览器数据之前，务必先导出

九、改代码的规矩

  1. 每个功能必须被分区标记包裹，START 和 END 的功能名一字不差（HTML 和 JS 两处都要）
  2. 数据读写只走 Store.*
  3. 输入框 font-size 不能小于 16px（否则 iOS 会自动放大整页）
  4. 数组型数据用 upsert / softDelete，不许 set 整包覆盖
  5. 用户输入一律过 Util.esc()（防 XSS）
  6. 图片必须过 Util.compressImage()（否则几张手机原图就撑爆存储，所有功能一起失效）
  7. 顶部和底部留 env(safe-area-inset-*)（全面屏会被状态栏/横条盖住）
